# Slack Clipper

在 Firefox 或 Chrome 里打开文章，点击工具栏图标，即可把标题、原文链接和完整可读正文发到指定的 Slack 频道。只想分享一段？先选中文字再点击。无需账号后台、OAuth 服务或云端提取。

## 安装

已有 ZIP 时不需要 Node.js。请先解压与浏览器对应的文件；`manifest.json` 位于解压后的根目录。

- Firefox 桌面版 142+：打开 `about:debugging#/runtime/this-firefox`，选择「临时载入附加组件」，打开 Firefox 包内的 `manifest.json`。在扩展菜单中将 Slack Clipper 固定到工具栏。
- Firefox 临时加载的未签名扩展会在重启后卸载。此处的 ZIP 不是已签名的 XPI。普通发行版要长期安装，需取得 Mozilla 签名，例如通过 AMO 的非公开分发流程签名后安装 XPI。不必公开上架，也不要关闭浏览器的签名检查。本次构建不签名、不上传。
- Chrome 桌面版 120+：打开 `chrome://extensions`，启用「开发者模式」，选择「加载已解压的扩展程序」，选中 Chrome 包的解压目录。保留该目录，在扩展菜单中固定工具栏图标。

从源码构建时，使用 Node.js 22.13+ 和 npm：

```sh
npm ci
npm run build
```

可以直接加载 `dist/firefox/` 或 `dist/chrome/`。扩展包是 `artifacts/slack-clipper-firefox-1.0.2.zip` 和 `artifacts/slack-clipper-chrome-1.0.2.zip`；`artifacts/slack-clipper-source-1.0.2.zip` 是用于重建的源码包，不能直接安装。参见[版本说明与审核步骤](RELEASE-1.0.2.md)。

## 配置和分享

1. 在自己的 Slack 应用中启用 Incoming Webhooks，选择「Add New Webhook to Workspace」，授权目标频道，复制生成的地址。如果组织限制安装应用，联系工作区管理员。
2. 第一次点击扩展图标只会打开设置。输入频道标签（例如 `#reading-room`）和 webhook，点击「Save destination」。标签仅用于本机提示。实际投递的频道由 Slack 绑定，不能通过改标签切换。保存时不会联网验证或发送测试消息。
3. 回到要分享的网页，检查正文和地址中是否有私人信息，再点击工具栏图标。未完成设置就关闭页面不会留下待发任务。已有配置时，重新打开扩展的设置页可替换或删除目的地。
4. 查看图标徽标，把鼠标停在图标上查看详细状态及 `已确认数/总数`。比如 `1/3 confirmed` 表示只收到第一条的成功回执，不代表全文已到达。

| 徽标  | 含义与处理方式                                                   |
| ----- | ---------------------------------------------------------------- |
| `SET` | 尚未配置。保存后回到原网页，重新点击才会发送。                   |
| `…`   | 正在提取或发送。等待结果，不要连点。                             |
| `OK`  | 所有分段均收到 Slack 的 HTTP 200 和正文 `ok`。                   |
| `!`   | 未能开始，或部分发送后停止。查看原因、回执计数和限流等待时间。   |
| `?`   | 当前分段可能已送达，但未获得可靠回执。先到频道核对分段编号。     |

## 长文与限流

不截取前几千字。扩展先为全文分段，再开始发送。每条消息都有标题、原链接和序号（如 `Article · 2/3`）。正文使用 Slack 富文本：标题独立成行并加粗；保留粗体、斜体、链接、列表、引用、行内代码及代码块的缩进。每个正文块按最多 3,000 个 UTF-16 单元（含链接地址）和 64 个行内元素分配，每条最多 8 个正文块。跨块时保留文字、链接和样式，不拆开代理对。普通文章通常只需一条。

- 每次只有一个发送任务，包含其他标签页在内。各段串行投递，上一段确认后至少等待 1.1 秒才发下一段。重复点击不排队；发送后有 4 秒防连点保护。
- 每条请求最长等 12 秒。限流（429）、明确拒绝、超时、网络中断或异常回执都会停止后续投递。遇到 429 时提示 `Retry-After` 秒数；没有有效值时按 60 秒处理。不自动重试，不跟随重定向。
- 网络断开不等于消息未发出。已经成功的部分不会撤回。再次点击会从头开始，而非断点续传。先核对频道，必要时只选尚未收到的段落再分享。关闭或重载浏览器可能中断任务；扩展不保存正文、进度或重试队列，后台重启后也不会恢复冷却计时。
- 保护上限：格式过密、需要超过 16 条消息时拒发。正文或选区超过 240,000 个 UTF-16 单元、标题超过 3,000 个单元、原始 URL 超过 2,048 个单元，或链接转义后无法放入 Slack 区块时，整篇拒发，不发送前缀。若未选中文字，超过 50,000 个元素的页面不解析。可改选较短的文字；选区不会绕过标题或 URL 限制。

## 隐私、权限与适用范围

`activeTab` 和 `scripting` 用于点击后在当前标签页的主文档提取正文。没有常驻内容脚本，不申请读取所有网站或浏览历史的权限。`https://hooks.slack.com/*` 主机权限用于后台向 Slack 发送请求；实际仅接受 HTTPS 的 `/services/` 三段地址，不允许认证信息、端口、查询、片段或重定向。若撤销了该主机权限，需在扩展权限设置中重新允许。

Webhook 是可以向频道发言的秘密。仅扩展设置页和后台访问扩展来源的本地 IndexedDB。不使用同步存储，不将 webhook 传给网页脚本，不记录 webhook 或文章。此存储不是加密密码库；能访问浏览器配置文件的人可能读到它。「Forget destination」只删除本机配置，不会在 Slack 撤销 webhook，也不能取消已发出的请求。泄露时请在 Slack 撤销并更换。

原文 URL 包含查询与片段，正文可能来自登录后的页面。分享前请确认频道成员可以看到这些内容。扩展不向其他服务传输数据，不做统计，不加载远程代码。标题和正文不作为 Slack 标记解析，`@here` 与 `<!channel>` 等文本不会触发群体提醒。正文中的 HTTP(S) 链接使用独立的 `link` 元素；无效或不支持的地址只保留可见文字。仅扩展构造的原文链接使用链接语法，并关闭链接预览。

「完整」指 GitHub 仓库首页中识别出的 README、其他页面由 Mozilla Readability 识别的正文，或单个连续选区中的可见内容，不代表整站、分页内容或精确排版。段落按网页语义合并空白；预格式文本保留空格、制表符和换行。过滤控制字符；图片、视频、PDF、子框架和未加载的内容不在范围内。浏览器内部页面、扩展商店等受限页面可能无法注入脚本。没有可读内容或无法访问页面时不发送。扩展只支持标准 Slack webhook，不支持 GovSlack 或自定义代理。

## 验证

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run lint:firefox
```

测试使用本地 HTML、虚构地址和替代 `fetch`，不访问 Slack。覆盖提取、选区、逐块拼回全文、大小边界、链接与提及安全、地址校验、并发点击、部分成功、限流及不确定回执。当前版本沿用带两处 DOM 修复的 Readability 0.6.0，差异和许可证见 `vendor/readability/`。`lint:firefox` 将警告视为错误。

不联网的手工检查：在一次性浏览器配置中临时加载扩展，点击图标打开设置。关闭未保存的设置，再点图标应再次要求配置。输入无效地址应提示错误且不保存。测试正常发送和分段反馈请使用上述模拟测试，不要为测试提供真实 webhook。

参考：[Slack Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)、[Slack 限流](https://docs.slack.dev/apis/web-api/rate-limits/)、[Mozilla 签名与分发](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/)。
